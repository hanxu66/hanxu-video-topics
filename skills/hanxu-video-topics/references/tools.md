# 工具与记录

本包不内置平台抓取服务。先检查当前AI环境实际提供的合法搜索/浏览/连接工具，再决定搜索、仅整理用户资料或明确受阻。不能把安装成功当搜索已运行，也不绑定作者电脑、登录状态或API服务。不要自动购买、安装第三方工具或新建定时任务。

优先直接读取可访问的原始作品题面；网页搜索摘要仅为发现线索，未取得原页时标范围。无法访问链接时可整理用户已给的截图/文本，未见字段保留未知。登录/验证码按平台正常流程交用户处理，不绕过；局部受阻留断点，继续其他可用来源。

## 本地可选库工具

Python 3.9以上，仅标准库。脚本无网络功能，不计算推荐分、不判断来源真假、不理解语义，操作者负责事实和状态判断。

在当前用户项目选择一个安装包之外的目录。以下路径均替换为实际路径，不要求用户逐条运行，可由AI用本地执行工具操作：

```sh
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 init
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 merge --input /用户项目/本轮选题.json
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 list
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 feedback --id 实际题目ID --quote '用户本次真实原话' --status 已选
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 export
```

`profile.json`由[空白模板](profile-template.json)初始化，为本用户配置；`library.json`为唯一题库；`选题库.md`仅为展示视图，包含每题的回想提示。用户指定输出路径意味着允许保存本任务记录；否则先在对话整理，需保存时确认目录。已有目录恢复原库，不初始化覆盖。反馈命令只允许在本人确有相应原话/事实时执行，脚本无法认证原话真假。

## 报告文件保存

有文件工具且需要保存报告时，默认先用文件编辑工具创建UTF-8的`outputs/report-draft.json`，内容为`{"markdown":"可读报告全文","record":{"本轮真实结构记录":"……"}}`；它是数据，不是待执行代码。不要用长中文Python heredoc拼报告，也不要把添加coding声明当成已修复传输编码的证据。

然后用包内固定保存器，命令只含路径和文件名：

```sh
python3 /技能实际位置/scripts/topic_library.py --workspace /用户工作目录 save-report --input /用户工作目录/outputs/report-draft.json --name 接续报告-r1
```

它显式按UTF-8读取草稿、保存`outputs/接续报告-r1.md`和`.json`，逐字节读回并返回校验值。JSON结构、中文、引号和换行原样作为数据处理；文件存在时拒绝覆盖，换新名称保留历史。读取时间、反馈和观察时间只写实际已知信息，保存器不代填或推断；返回的saved_at仅为本次实际保存时间。草稿不是最终交付，须检查保存器成功结果与最终文件后才报告已保存。

只有文件编辑能力时也可直接写UTF-8报告并重新读取检查；无文件工具时在对话交结果，明确未保存。遇编码错误先保留失败记录，不改题库或全局编码设置，也不反复重传同一大段执行代码。

## 反馈保存与接续

`feedback`保存原话，`--scope`可标`改写`、`核心问题`、`本轮`或`长期偏好`。范围根据用户实际表达填写；不清楚时保留未标注，不能由脚本推断。`--status`单独表示有明确依据的整题状态变化。仅否定改写不能改变整题状态，需要明确选题或停用时另记一条对应反馈。

以下为合成操作示例，实际调用须换成本次用户原话与真实题目ID：

```sh
# 只否定AI改写：保留来源、问题和原题状态
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 feedback --id 实际题目ID --scope 改写 --quote '原问题有启发，你改成工具教程我不想拍'
# 整轮偏好不硬挂到某个题目，也不批量否定已有题
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 feedback --scope 本轮 --quote '下一轮多找供应商沟通，这轮先不找工具教程'
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 export
```

无`--id`时仅允许记录`本轮`或`长期偏好`，不能传`--status`。脚本不自动改配置或生成查询；明确的长期偏好由助手按原话同步到本用户`profile.json`，并保留依据。单次反馈不能变成其他用户的规则。

导出的题库包含反馈原话、范围、题目和记录时状态；历史事件不表示全部仍有效，旧记录缺范围显示待核对。继续任务时读配置、完整题库与反馈，再说明本次查询怎样改变；题目或来源细节以JSON为准，不只看标题与状态。无文件工具时在对话保留同样的反馈接续信息，不声称已落盘。

背景补充的跨轮归属按[用户配置：跨轮背景补充](profile.md#跨轮背景补充)保存。恢复时不把旧配置中的`received_this_round`或“本轮新提供”当作新反馈；仅在明确授权并备份后修复旧标记，缺失的历史时间与轮次不补造。

恢复时同时核对反馈时间、明确对象和题目创建时间。“其他先留着”只说明当时其余题未被否定，不能替之后新增的题补选择、否定或背书；明确长期偏好仍按其原话范围判断，不能因题目较新就忽略长期限制。时间或范围缺失时保留待核对，不从文件顺序猜。

## 导入格式

导入JSON为数组。下面是合成格式示例，不能用作真实搜索产物：

```json
[
  {
    "question_key": "自由职业者/第一次额外修改/确认工作范围",
    "topic": "第一次答应额外修改时，先确认什么",
    "audience": "刚开始接项目的自由职业者",
    "inspiration": "可以讲清额外修改怎样影响项目；具体经历由本人补充",
    "recall_prompt": "哪次客户说只改一点，你当时怎样答应，后来多做了什么？",
    "status": "储备题",
    "interest_judgment": "格式演示，真实兴趣未验证",
    "missing": ["本人材料待展开"],
    "sources": [
      {
        "platform": "user-provided-synthetic-example",
        "ref": "example:synthetic-A",
        "raw_title": "客户说只改一点，最后却重做三天（合成题面）",
        "description": null,
        "tags": null,
        "observed_at": "2026-10-22T12:00:00+08:00",
        "evidence_scope": "metadata_only",
        "metrics": {"likes": null, "followers": null},
        "discovery": {"route": "provided_materials", "query": null}
      }
    ]
  }
]
```

实际时间用真实观察时间，未知为`null`，不填0。来源`evidence_scope`可为`metadata_only`、`user_statement`、`article_text`，只反映实际读取。`ref`为链接或本地/对话可回读引用。私密凭据和登录URL不作为来源保存。

v0.2.0新导入须提供非空`recall_prompt`，即适配该用户的具体回想提示；脚本只检查字段，是否能唤起经历仍由执行者检查和用户反馈验证。旧库仍可读取与导出，缺提示显示待补；补充研究时可填入提示，不改变原选择或标题。已有提示的新建议保存在`supplements`，保留原措辞和反馈。

新补充记录包含`id`、`topic_id`、`at`、`field`、`value`及`source_observations`。`at`是本地保存建议的真实时间；每个关联来源保留平台、规范链接`ref`和原`observed_at`，不能拿保存时间代替观察时间。关联表示随建议提交的材料，语义依据是否足够仍由执行者检查。相同建议与相同来源观察再次导入不重复记事件；同建议有不同来源观察可另留事件。旧记录缺ID、时间或关联来源就显示“未记录”，不推算补造。

导出的展示视图保留原提示，并单列补充角度、新提示与关联依据；每题分别显示来源观察次数、去重作品数和最近来源观察时间。统计不把反馈、导入或复评时间算来源观察；未知日期不填当前时间。详细来源与事件仍以`library.json`为准。

同核心问题复用`question_key`，脚本按该键合并；先由AI按观众任务/决策作语义判断。不同问题不能复用同键，同义标题也不能新造键。来源不同时间的观察全部保留，未知新观察不擦除旧数据。再次导入不覆盖用户的选择与措辞，新建议保存在补充记录。

`merge`中`status`仅用于新题；同问题补充时，即使传了不同状态或省略后默认成储备题，也保留旧状态。补了来源不等于优先级、可讲角度或用户意愿已经改变。

## 事件ID与历史记录

新补充、研究复评及用户反馈事件均保存`id`。反馈在题内与整轮列表中的两份视图使用同一ID。来源观察通过平台、规范链接及原观察时间定位；补充中的来源关联只表示随建议提交的材料，不推断作者已经支持全部建议。

普通读取、导出和补来源不自动改造历史。需要给旧事件补发标识时，先核对用户授权，再在自己的工作目录执行：

```sh
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 index-events
```

该操作先保存原`library.json`逐字节备份，再只给没有ID的补充、复评、反馈添加`id`、`id_origin=indexed_legacy`和真实的`id_assigned_at`。它们是现在分配的记录标识，不冒称历史原生ID；分配时间不是历史事件发生时间。原有ID不变，重复运行不再改文件。旧事件缺`at`、原话范围或来源关联仍缺，不推算补齐，不改题目措辞、选择、复评结论及来源观察。题内和全局完全一致的反馈视图共用一个ID，不能把它们计为两次用户反馈。

## 明确复评

只有本次明确要复评、且有可解释的新依据时，单独调用`reassess`；它不随`merge`自动运行。先回读当前题目和状态，逐题提供`--from-status`、目标`--status`、`--reason`。下面仅为合成格式示例，不是对某个真实题目的升级结论：

```sh
python3 /技能实际位置/scripts/topic_library.py --workspace /用户项目/短视频选题 reassess --id 实际题目ID --from-status 待补角度 --status 储备题 --reason '合成演示：新材料提供了具体可回想的沟通场景；真实使用效果未知'
```

复评只处理无用户反馈的研究状态（储备题、待补证据、待补角度、只借题面、优先备选）。当前状态与`--from-status`不符、依据为空或该题已有用户反馈时拒绝写入，先核对现状；不能借复评重置已选、已拍、已发布、暂缓或不再使用。明确的用户决定仍按原话用`feedback`记录，已有反馈不会被研究复评擦除或重新解释。

复评追加`status_reviews`中的原状态、新状态、时间与依据，并在可读导出中展示；不改题目措辞、旧来源或反馈。脚本只检查显式字段与状态边界，不能验证理由是否属实、是否足以升级为优先备选；执行者仍须按实际证据判断。旧库不需迁移。

新复评事件另有可定位的`id`；旧事件没有ID就保留缺项。复评的`at`只表示复评记录时间，不重写任何来源观察时间，也不变成用户反馈。

将实际查询、成功/失败、覆盖、来源关系、纯联想待验证及断点保存在用户目录的本轮记录中。纯AI联想没有来源时不使用`merge`假装有证据入库。脚本原样保留扩展字段，调用方不能塞入私密凭据或把模型推测当原话。
